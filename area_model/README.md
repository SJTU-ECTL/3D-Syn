# Routability-Aware Area Estimation Model

The area model predicts a coarse unit's post-route utilization from its mapped
standard-cell netlist. Coarse synthesis uses this value to derive the physical
footprint supplied to partitioning.

## Layout

| Path | Responsibility |
| --- | --- |
| `config.py` | Repository paths, platform mapping, and feature definitions |
| `model.py` | GraphSAGE utilization model |
| `dataset.py` | Shared graph-sample and normalization contract |
| `predict_util.py` | Command-line inference interface used by the flow |
| `train.py` | Standalone training entry that produces inference-compatible checkpoints |
| `data_generation/` | Numbered offline RTL-to-routed-label data pipeline |
| `resources/` | Cell vocabulary, port schema, simulation library, and virtual-clock SDCs |
| `pretrained/` | Validated ASAP7 and Nangate45 inference checkpoints |

Inference imports only `config.py` and `model.py`; it does not depend on data
generation or model training code.

## Prediction interface

Run inference with the configured Python environment:

```bash
flow/env_isolation/python_launcher.sh area_model/predict_util.py \
  path/to/mapped_netlist.v \
  _add_A8_B8_Y9 \
  bottom \
  --platform-dir "$SYN3D_TAIWEI_HOME/TaiWei-Pin-3D/platforms/asap7_nangate45_3D"
```

The launcher isolates the selected Python environment's PyTorch libraries
from Cadence and OpenROAD subprocesses.

The technology argument selects one checkpoint without fallback:

| Technology | Cell library | Checkpoint directory |
| --- | --- | --- |
| `bottom` | Nangate45 | `pretrained/nangate45/` |
| `upper` | ASAP7 | `pretrained/asap7/` |

Use `--checkpoint-root PATH` to select another root containing these platform
directories. `--resources-dir PATH` can select another compatible vocabulary
and schema. The command prints one utilization value in `(0, 1]` to standard
output; diagnostics are written to standard error.

## Checkpoint contract

Each platform directory contains:

```text
best_model.pt
norm_stats.pt
config.json
manifest.json
```

The manifest records the platform and technology, model and feature format,
feature ordering, resource identity, checkpoint checksums, training summary,
and evaluation metrics. Inference verifies this metadata before loading the
model and rejects missing, modified, or cross-platform artifacts.

The mapped netlist must use cells in `cell_type_vocab.json`. Its wrapper ports
must exactly match the canonical type in `port_schema.json`; the type is the
first token of the wrapper name, such as `ADD` in `_add_A8_B8_Y9`.

## Offline generation and training

Offline data generation and training are independent workflows and are not
invoked by the root Makefile or the runtime prediction interface. See
`data_generation/README.md` for the numbered two-process data pipeline. After
building all desired groups, train one process model with:

```bash
python3 area_model/train.py \
  --technology asap7 \
  --data-root /path/to/area-model-work \
  --resources-dir /path/to/area-model-work/00_resources \
  --output-dir /path/to/checkpoints/asap7 \
  --epochs 300 --batch-size 32 --seed 42
```

Use `--technology nangate45` and a separate output directory for the other
process. Training consumes the deterministic `splits.json` generated by step
05 and writes model weights, normalization statistics, configuration, history,
metrics, split metadata, and a checksum manifest. Supply the resulting
checkpoint root and matching generated resources to `predict_util.py` when
validating a newly trained model.
